## 追加问题分析与修复

- 原拖拽逻辑以 `files[0].type === ''` 判断目录，导致没有 MIME 的 LOG、CJS 被误拒绝，并阻止同批其他文件上传。
- 改为在原生 drop 捕获阶段读取 `DataTransferItem.webkitGetAsEntry()` 的目录标记，再过滤目录；不再依据 MIME 或 0 字节大小判断文件夹。
- 同步修复消息归一化和 SQLite 写入将 0 字节转换为 null 的问题，确保空文件大小在实时消息和重启后的历史中保持为 0 B。
- 无目录识别 API 时不猜测普通文件为目录，继续正常文件上传流程。粘贴、选择文件和拖拽保持兼容。
- 文件消息、批量列表和预览窗口独立展示扩展名；长文件名可省略，但格式与大小保留。
- 普通文件复用原 FilesCard 灰底与分类图标，增加克制边框，悬停和聚焦时增强反馈；Pin、置顶、多选仍使用已有状态样式。
- 源码、配置与 Markdown 的原文预览已按扩展白名单启用，语法高亮与 Markdown 阅读模式留待后续实现。
- 追加 Chrome 验证通过：空 MIME 的 LOG/CJS 原生拖拽、模拟目录条目与空文件混合拖拽、长中文文件名在 390px 视口下的独立格式和大小，以及更明显的文件卡片样式。目录条目通过浏览器 API 模拟，不等同于操作系统文件管理器的真机拖拽验收。
