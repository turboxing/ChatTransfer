# 附件内容预览实现方案

- 状态：第一阶段已实现，待合并与发布；移动设备真机兼容性待验收。
- 日期：2026-11-21。
- 范围：文件消息、已有图片预览和批量下载页面的预览入口。

## 1. 现状、痛点与目标

ChatTransfer 用于在电脑、手机和测试设备之间传输文字、图片、日志、配置文件与录屏。图片已有预览能力；其他附件往往需要先下载，再通过其他应用查看，增加临时传输的操作成本。

目标是在下载前查看附件内容，支持阅读、搜索、复制和媒体播放，并让用户在消息列表中直接看到文件大小，以判断下载成本。复用现有房间、附件下载和图片预览能力，保持旧消息兼容。

典型场景：

1. 收到 LOG 文件后直接搜索错误信息，不必下载整份日志。
2. 打开 JSON 或 CSV，确认配置和数据是否正确，再复制或下载。
3. 收到 PDF 或录屏后直接查看，确认是否为所需资料。
4. 手机用户在消息卡片上看到附件大小，再决定是否打开或下载。
5. 批量下载前逐个预览，确认内容，同时保留已选择的附件。

## 2. 第一阶段支持范围

| 类型 | 预览方式 | 失败或不支持时 |
| --- | --- | --- |
| TXT、LOG | 纯文本阅读、搜索、复制、换行与编码切换 | 提示原因并提供下载 |
| JSON | 完整且合法时默认格式化，支持切换原文 | 格式不合法时按文本展示 |
| CSV | 原文展示，保留换行和分隔符，支持搜索与复制 | 不提供表格编辑 |
| PDF | 浏览器原生内嵌预览，始终提供独立打开入口 | 提供下载 |
| 音频 | 复用文件卡片，点击后在消息原位展开原生播放器 | 提示格式或编码不支持并提供预览和下载 |
| 视频 | 播放封面卡片，点击后弹窗播放，支持原生全屏 | 提示格式或编码不支持并提供下载 |
| 图片 | 沿用现有图片预览 | 保持已有下载入口 |
| 其他格式 | 文件名称、类型、大小与下载操作 | 不解析文件内容 |

第一阶段不解析 Office 文档、压缩包或可执行文件，不提供音视频转码，不执行 HTML、SVG 等主动内容。

## 3. 文件大小展示（明确验收要求）

### 3.1 文件消息卡片

文件消息必须在下载、打开预览之前直接展示大小，不能仅在弹窗中展示，也不能依赖鼠标悬停。桌面端与手机端均适用。

建议布局：

```text
[文件图标] regression.log
           LOG · 2.4 MB
```

- 适用于发送和接收的文件消息，包括文本文件、PDF、音视频与不支持预览的格式。
- 卡片点击打开预览或媒体；下载通过更多菜单或预览窗口进行，音频展开后可收起播放器。
- 发送中的文件可使用浏览器提供的文件大小；发送成功后以服务端确认值为准。
- 预览窗口顶部、批量下载附件列表同样展示完整文件大小。
- 文件名过长可以省略显示，但大小不能被挤出视图；弹窗中支持查看完整文件名。
- 图片的已有缩略图样式保持兼容，其预览信息区也应展示大小。

### 3.2 数据与格式规则

- 以服务端附件元数据中的字节数为依据，不能根据文件名称推断大小。
- 使用统一格式化函数；为延续常见界面表达，按 1024 进位显示 B、KB、MB、GB，大于 B 的单位最多保留一位小数，去掉无意义的末尾零。
- 0 字节明确显示 `0 B`；未知大小显示“大小未知”，不能误显示成 0。
- 旧消息优先复用已持久化的附件大小；缺失时由服务端在附件查询或预览时读取文件元数据并补充。不要为了填充列表大小而下载文件正文，也不要对所有历史消息逐条发起请求。
- 截断预览仍展示完整附件大小，并另外注明已预览范围。例如：`LOG · 20 MB`，配合“仅预览文件前 1 MiB”。
- 具体元数据字段在实施时根据现有代码确认，尽量复用并以新增可选字段方式兼容旧消息与客户端。

## 4. 统一交互

普通文件点击卡片打开预览。复用原有 FilesCard 的分类图标、文件名和描述布局，描述独立显示真实扩展名与大小。不再在每张成功文件卡片内常驻“预览、下载”文字按钮；下载保留在更多菜单和预览窗口。悬停仅高亮并提示“点击预览”，不自动弹窗。

预览界面分为三部分：

1. 顶部：完整文件名、类型、完整文件大小与关闭按钮。
2. 中间：内容、播放器、加载状态或错误说明。
3. 操作区：下载，以及按类型显示的复制、编码选择、原文切换、独立打开等操作。

桌面使用大弹窗，手机使用接近全屏的预览界面，内容独立滚动。关闭预览后回到原消息位置，不触发自动滚动到底部。

批量下载页面复用同一预览入口：名称或缩略图负责预览，勾选框只负责选择。打开、关闭或预览失败均不改变选中项。

## 5. 文本阅读细节

| 项目 | 第一版建议默认值 |
| --- | --- |
| 最大读取范围 | 文件前 1 MiB，即 1,048,576 字节 |
| JSON 格式化上限 | 完整文件不超过 1 MiB |
| 自动识别编码 | UTF-8、带 BOM 的 UTF-16 |
| 手动编码切换 | UTF-8、GB18030；保留自动识别到的 UTF-16 选项 |
| 搜索范围 | 当前已加载的预览文本 |

超过上限时只读取文件开头，并提示：

> 仅预览文件前 1 MiB，搜索和复制仅针对当前预览内容。下载可查看完整文件。

- 搜索按普通文本匹配，显示匹配数量，支持上一个和下一个。限制过多匹配的高亮渲染，避免冻结页面。
- 默认自动换行，提供开关，便于阅读长日志。
- 复制按钮命名为“复制预览内容”，明确当前范围；JSON 格式化模式下复制当前展示文本。
- 完整 JSON 解析成功后格式化；截断内容不尝试格式化，解析失败不阻止阅读原文。
- CSV 第一阶段按文本展示，不加入表格解析与编辑依赖。
- 解码时处理截断造成的不完整字符；疑似二进制内容停止文本展示，提示下载。
- HTTP 局域网环境使用可行的剪贴板兼容方式，失败时允许选中并手动复制，不能虚报成功。
- 文件大小限制不等于渲染开销可忽略，文本显示和搜索需避免为每个字符创建独立 DOM 节点。

## 6. PDF、音视频行为

PDF 优先复用浏览器原生能力，不引入 PDF.js。始终提供“在新窗口打开”和“下载”；不能将 iframe 加载完成当作 PDF 一定成功显示，避免移动端白屏无出路。

音视频使用原生 audio、video 控件，点击后才获取短期预览地址并加载媒体，不在打开会话时批量请求元数据。需要支持播放进度拖动；手机端允许内联播放和全屏。扩展名不能保证编码受支持，最终以播放器加载、播放结果为准，错误时显示下载入口。

- 音频：卡片保留播放按钮，点击后原位展开播放器并尝试播放；浏览器拦截自动播放时由用户点击原生控件继续。再次点击可暂停，支持收起并卸载媒体源。
- 视频：使用 16:9 播放封面卡片，点击后打开弹窗并尝试播放。当前无预生成封面时显示视频播放占位图，不提前下载录屏来提取首帧；真实封面提取留待后续评估。
- 全会话窗口共享播放控制，包括消息列表、Pin 列表和预览弹窗，同一时间只允许一个音视频播放。开始新音频、打开预览、切换房间、进入多选或关闭 Pin 列表时停止上一播放器。
- 多选模式点击卡片仅切换选择，不播放、不打开预览。

关闭预览、切换房间或退出房间时停止播放和网络加载，取消未完成请求并释放临时资源。第一阶段不做服务端转码。

## 7. 服务端方案与安全边界

先检查现有附件查询、下载和访问控制实现，复用文件定位与授权逻辑。实现阶段再确定接口名称，不在本方案中承诺未经验证的现有字段或路由。

### 7.1 文本预览

根据附件 ID 和所属房间定位文件，先读取元数据，再以流或指定范围读取最多 1 MiB，不能先将大文件完整读入内存再截取。返回或提供完整大小、读取范围、是否截断与编码所需信息。

### 7.2 流式媒体预览

PDF 与音视频复用受访问校验保护的流式接口。核对 Range 支持并正确处理 206、416、Content-Length、Content-Range 和媒体类型。预览与下载可区分 Content-Disposition，下载入口继续保持附件下载行为。

浏览器原生播放器、iframe 不能直接携带任意自定义请求头，需要根据现有权限模型设计可用的访问方式；如需预览令牌，应限制附件、房间、有效期与用途，不使用长效公开地址绕过权限。

### 7.3 约束

- 客户端不能传入服务器绝对路径或任意文件系统路径。
- 预览与下载权限一致；若发现现有权限缺口，应在实施前明确解决。
- 房间解散、用户失去访问权限或附件清理后，新的预览请求必须被拒绝。
- 文本以纯文本安全展示，不使用 HTML 执行文件内容。
- 文件类型综合可信元数据、扩展名和必要内容检查决定，不能直接信任上传方声明的 MIME。
- 预览不改变消息保留期，也不重置房间闲置计时。
- 清理导致附件不可用时，提示“附件已被清理或不存在，无法继续预览”。
- 已加载到浏览器内存或已下载的内容不能远程撤回；关闭预览时释放应用持有的资源。
- 预览正文、文件名不进入统计事件或常规请求日志正文。

## 8. 前端结构建议

| 模块 | 职责 |
| --- | --- |
| AttachmentPreviewDialog | 统一容器、元数据、完整大小、加载和错误状态 |
| TextAttachmentPreview | 文本、编码、搜索、复制、格式化与换行 |
| PdfAttachmentPreview | 内嵌预览、独立打开和下载 |
| MediaAttachmentPreview | 音视频控制、错误处理与资源释放 |
| AttachmentInfoPreview | 不支持类型的信息与下载 |
| 预览 composable | 打开、请求取消、结果隔离、资源释放、房间切换 |
| 大小格式化工具 | 统一消息卡片、预览与批量下载列表的展示 |

消息列表与批量下载页面调用统一入口。快速切换文件时取消旧请求，校验当前附件身份，避免旧文件响应覆盖当前预览。

## 9. 影响范围与兼容

- 文件消息卡片：大小展示、点击预览与下载事件分离。
- 批量下载页面：统一大小展示和预览入口，保持选择状态。
- 附件服务：有限读取、元数据补全、媒体分段请求与权限检查。
- 房间生命周期：关闭预览、停止播放、撤销访问。
- 中、英、阿拉伯语：新增状态与操作文案。
- 原则上不改变消息类型或历史表；若实际缺少必要元数据，实施前明确兼容性补充方案。
- 已有历史附件仍存在且可访问时，应支持新预览功能。

## 10. 验收与自测

1. 发送和接收的文件卡片直接显示大小，桌面与手机均无需打开弹窗；长文件名不遮挡大小。
2. 0 B、普通大小、大文件和未知大小展示正确，预览顶部与批量下载列表一致。
3. 旧消息缺少大小时不显示伪造值，可基于服务端元数据恢复。
4. TXT、LOG、JSON、CSV 可阅读、搜索、复制，中文编码切换有效。
5. 超大文件只读取上限范围；完整大小、截断提示、搜索及复制范围一致。
6. 二进制伪装文本、乱码、异常 JSON 不导致页面崩溃。
7. PDF 内嵌不支持时始终可独立打开或下载。
8. 音视频播放与进度拖动正常；不支持编码时有明确提示。
9. 快速切换附件不串内容；关闭预览、退出或切换房间后停止播放与加载。
10. 预览不改变消息滚动、Pin、置顶或批量选择状态。
11. 验证跨房间越权、路径穿越、令牌失效、文件过期、房间解散及 Range 异常请求。
12. 检查桌面 Chrome、Safari、手机 Safari 和 Android Chrome；模拟视口不能替代真机播放与下载验证。

## 11. 实施顺序与估算

1. 核对附件元数据、旧消息兼容、大小展示和现有访问控制。
2. 实现统一弹窗与文本预览。
3. 接入 PDF、媒体分段读取与播放器。
4. 接入批量下载页面、多语言和资源释放。
5. 完成回归与移动端自测。

完整第一阶段估算 5–8 个工作日，包含基本异常处理、文件大小展示与兼容验证；现有权限或 Range 能力的缺口可能增加成本。CSV 表格视图、Office 解析、压缩包浏览和音视频转码留待后续评估。

## 12. 本地实现说明

- `attachment_preview` Socket.IO 事件使用当前连接身份和活动房间校验，返回单附件、10 分钟有效的随机凭证及真实文件大小。
- `/attachment-preview/:token` 每次访问重新检查成员权限、附件记录及实际文件；原生播放器可以使用该地址进行 Range 请求。
- `?text=1` 在服务端最多读取 1 MiB；`?download=1` 返回下载响应。其他格式不内嵌执行。
- 文本、媒体和 PDF 使用统一弹窗，消息卡片、Pin 列表与批量下载页面共用入口。图片保留原有放大交互，同时在消息卡片补充大小。
- 消息列表音频改为原位播放，视频和普通文件继续使用统一弹窗；统一入口仍供批量下载等场景使用。
- 预览弹窗关闭或房间切换时取消文本请求、停止媒体播放并清理媒体源；当前房间收到历史清空事件时也关闭预览。
- 兼容旧消息缺失大小的情况，通过服务端文件元数据补全；不新增数据库表，不修改版本号或发布配置。
- 本次保护新增预览入口，未改造旧 `/files` 静态访问机制，也不声称为既有附件链接引入全面身份认证。
- 自测范围及尚未覆盖的真机环境见 [附件预览自测记录](./testing-report-attachment-preview.md)。

## 13. 源代码预览扩展方案（待确认，未启用）

源码可以复用纯文本预览，不需要在服务端执行代码或加载编程语言运行时。

1. 增加严格扩展名白名单，建议首批覆盖 JS、CJS、MJS、TS、TSX、JSX、PY、GO、RS、JAVA、C、H、CPP、CS、SWIFT、KT、SH、SQL、CSS、VUE、MD、YAML、YML、TOML、INI、XML。
2. 所有这些类型统一通过受权限保护、最多读取 1 MiB 的文本接口读取，沿用搜索、复制、编码切换和截断提示。上传不依赖浏览器是否提供 MIME；CJS 等类型当前允许上传，但扩展预览尚未启用。
3. 第一版只展示源码，不执行 JS、Python、Shell 等内容；Markdown 先显示原文，不解析 HTML 或加载外部图片，避免引入网络访问和脚本执行。
4. 语法高亮与 Markdown 渲染作为独立后续阶段：高亮组件按需加载，限制支持语言和处理内容长度；渲染 Markdown 时关闭原始 HTML，限制链接协议及外部资源，并补充安全与性能测试。
5. 扩展名未知、无扩展名或疑似二进制仍提供元数据和下载，不能仅因 MIME 为 text 就执行或渲染主动内容。

成本估算：纯文本扩展和回归约 0.5–1 天；语法高亮约 1–2 天；安全 Markdown 渲染约 1–2 天。无需数据库迁移，不改变房间消息模型。
