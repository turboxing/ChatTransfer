# 私有会话与删除会话需求方案

## 1. 结论

私有会话功能可行，而且对 ChatTransfer 的使用体验有明显提升。

当前服务端已经具备私聊消息传输、私聊历史查询和 SQLite 持久化能力，主要缺口在界面入口、会话列表、会话切换以及“删除会话”的产品语义。建议在在线设备列表上线后继续实现私有会话，因为在线设备列表可以直接作为“发起私聊”的入口。

## 2. 用户价值

群聊适合临时广播和多人协作，但以下场景更适合私有会话：

- 将测试日志、截图、录屏只发给某一台测试设备。
- 两台设备之间连续传输多个文件，不希望打断群聊内容。
- 发送包含内部信息、临时链接或测试账号的内容。
- 一对一调试时独立查看聊天记录和附件。
- 临时协作结束后，从会话列表中删除该会话及相关记录。

私有会话不会改变现有群聊入口。它是对群聊的补充，而不是替代群聊。

## 3. 使用场景

### 场景一：向单台测试手机发送文件

用户在在线设备列表中看到某台测试手机，点击“私聊”，建立私有会话并发送安装包、日志或截图。其他设备不会看到这些内容。

### 场景二：两台设备持续互传

电脑和一台手机需要连续传输多个文件。用户进入私有会话完成传输，避免群聊中出现大量只有双方需要的文件消息。

### 场景三：临时隐私内容

用户需要临时发送测试账号、内部链接或录屏，不希望长期保留在群聊中。传输完成后可删除该私有会话。

### 场景四：清理临时会话

一次性任务结束后，用户从会话列表中删除私有会话。默认只从自己的视图移除，并可选择彻底删除服务器记录。

## 4. 产品设计

### 4.1 会话入口

建议增加一个会话侧栏或抽屉，包含：

- 固定的“群聊”入口。
- 最近使用过的私有会话。
- 在线设备入口和“发起私聊”按钮。
- 每个私有会话展示设备昵称、IP、最后消息时间。

用户可以点击在线设备列表中的设备，直接创建或打开对应私有会话。

### 4.2 新建私有会话

- 只有选择具体用户时才创建私聊，不提供没有目标的空白私有会话。
- 首次打开时可以先显示空会话；发送第一条消息后再出现在最近会话列表中。
- 同两个人之间始终复用同一个私有会话，不创建重复会话。
- 自己不能与自己建立私有会话。

### 4.3 会话切换

- 切换会话时不刷新页面，直接重新加载对应私聊历史。
- 切换前保留当前输入框内容。
- 切换后清理附件选择、Pin 定位状态和临时提示。
- 私有会话只在参与者双方之间可见。

### 4.4 删除会话的产品语义

“删除会话”不能简单等同于删除消息。建议明确提供两个层级：

#### 从我的设备删除

- 从自己的会话列表隐藏该会话。
- 清空当前浏览器中的本地缓存。
- 不影响对方看到的聊天记录。
- 需要记录当前用户对该会话的删除游标，避免本地删除后又被服务器历史同步回来。

#### 为双方彻底删除

- 删除服务器上的所有消息、附件和会话记录。
- 对方在线时实时通知其会话已被删除。
- 必须使用危险操作二次确认。
- 提示文案明确说明“所有设备都无法恢复”。

第一版建议默认提供“从我的设备删除”，并将“为双方彻底删除”放在危险操作区。这样更符合用户对隐私和误操作的预期。

## 5. 技术可行性

### 5.1 已有能力

- `private_chat` Socket 事件已支持私聊消息传输。
- 私聊历史通过 `history_query` 查询。
- SQLite 已有 `sessions`、`session_participants` 和 `messages` 表。
- 私聊会话 ID 由两个参与者的用户 ID 计算得出，可复用。
- 私有会话中的文件和附件已有下载与批量下载基础能力。

### 5.2 需要补充的能力

- 私聊会话列表查询：返回最近会话、最后一条消息、时间和未读状态。
- 前端会话侧栏和会话切换状态管理。
- 私聊入口：从在线设备列表发起会话。
- 每个用户独立的会话删除游标或隐藏状态。
- 删除后阻止历史同步重新带回已删除消息。
- 切换会话时清理当前页面的临时状态。

### 5.3 推荐数据模型

建议新增 `conversation_user_state` 表：

- `session_id`
- `user_id`
- `deleted_at_seq`
- `hidden`
- `last_read_seq`
- `updated_at`

查询历史时过滤 `messages.seq > deleted_at_seq`，即可实现“只删除自己的视角”。如果选择“为双方彻底删除”，继续使用现有服务器历史清理流程删除消息和附件。

## 6. 影响范围

- `server/services/message-history-service.js`：会话列表、用户删除游标、历史过滤。
- `server/socket/index.js`：私聊创建/切换、删除通知和在线设备入口。
- 新增会话列表接口或 Socket 事件。
- `frontend/src/components/chat/`：会话侧栏、私聊入口、删除确认。
- `frontend/src/components/ChatLayout.vue`：无刷新切换会话。
- 本地缓存、Pin 状态、顶部消息、附件选择和多选状态的清理。
- 中英文案、E2E 测试和移动端布局测试。

## 7. 成本评估

| 工作项 | 预计成本 |
|---|---:|
| 会话列表与无刷新切换 | 1～1.5 天 |
| 在线设备发起私聊 | 0.5 天 |
| 个人删除游标与历史过滤 | 1～1.5 天 |
| 双方彻底删除与实时通知 | 0.5～1 天 |
| 本地状态清理、移动端和 E2E | 1 天 |
| 合计 | 4～5.5 个工作日 |

## 8. 风险与约束

- 当前没有账号体系，用户 ID 由浏览器生成，清理浏览器数据后可能无法恢复原会话。
- 局域网内目前没有端到端加密，私有会话只代表消息不广播给群聊，不代表服务端看不到内容。
- 删除会话时如果只删除本地状态，服务器仍可能保留记录，产品文案必须明确说明。
- 双方彻底删除会影响另一个用户的记录，需要高等级二次确认。
- 会话切换涉及 Pin、Top、附件、多选和输入框等多个局部状态，必须逐项清理。

## 9. 验收标准

- 用户可以从在线设备列表发起私聊。
- 私有会话不会出现在群聊消息流中。
- 双方可以正常收发文本、图片和文件。
- 会话侧栏能展示最近私有会话和最后消息时间。
- 无刷新切换会话后历史消息、附件和发送目标正确。
- “从我的设备删除”只影响当前用户视角。
- “为双方彻底删除”会删除服务器消息和文件，并通知对方。
- 删除会话后 Pin、Top、批量下载和多选状态不会残留。
- 刷新页面后，已删除或隐藏的会话不会重新出现。

## 10. 实施建议

建议拆成两个阶段：

1. 私有会话入口、会话列表、无刷新切换和基础私聊历史。
2. 个人删除游标、双方彻底删除、删除通知和完整 E2E 测试。

第一版优先保证“能建立私聊、能切换、能清理自己的视图”，再谨慎开放“为双方彻底删除”。
